# Domain docs

## Layout

This is a single-context repository:

- GLOSSARY.md at the repository root
- Architecture decision records under docs/adr/

## Before codebase exploration

Read the root glossary and ADRs relevant to the area being explored.

If either is absent, proceed silently. The domain-modeling skill
creates them when terms or decisions are resolved.

## Vocabulary

Use the glossary’s terms in issue titles, proposals, hypotheses,
and tests. When a needed term is absent, reconsider whether it
belongs to this domain or record the gap for domain-modeling.

## Decisions

Surface any conflict with an existing ADR, identifying the ADR
and explaining why the decision should be reopened.
